# МедМаршрут

Информационный чат-бот для первичной маршрутизации пациента (хакатон «МедВед.Код2», 2026).
Веб-приложение, которое открывается из мини-приложения мессенджера MAX (вход по профилю пользователя).

Бот собирает жалобы и анамнез, непрерывно проверяет ответы на экстренные признаки и выдаёт
карточку-рекомендацию: к какому специалисту, куда и насколько срочно обратиться, с обоснованием.
**Бот не ставит диагноз, не назначает лекарства и не заменяет врача.**

## Быстрый запуск

```bash
cp .env.example .env
docker compose up --build
```

Откройте http://localhost:8080. Документация API (Swagger) доступна внутри сети compose
по адресу `backend:8000/docs`; для локальной разработки — http://localhost:8000/docs.

Тесты:

```bash
docker compose run --rm tests
```

Без Docker:

```bash
cd backend && pip install -r requirements.txt && pytest
uvicorn app.main:app --reload            # API на :8000 (SQLite по умолчанию)
cd ../frontend && npm install && npm run dev   # интерфейс на :5173, /api проксируется на :8000
```

## Архитектура

```
[Мини-приложение MAX / браузер]
        │  React (Vite), nginx
        ▼
[nginx :8080] ── /api ──► [FastAPI :8000] ──► [PostgreSQL 16]
                              │
                              ├─ domain/       движок диалога, экстренные признаки, маршрутизация (чистый Python)
                              ├─ services.py   связь домена с БД
                              ├─ api.py        REST API v1
                              └─ integrations/ клиент core MAX ──► core организаторов (профиль пользователя)
```

| Слой | Технологии | Почему |
|---|---|---|
| Backend | Python 3.12, FastAPI, Pydantic v2 | Валидация из коробки, автодокументация OpenAPI, быстро писать |
| Данные | PostgreSQL 16, SQLAlchemy 2.0 | Надёжная СУБД, ORM без привязки к конкретной БД (тесты на SQLite) |
| Frontend | React 18, Vite, nginx | Лёгкий SPA (≈50 КБ gzip), подходит для WebView мессенджера |
| Безопасность | cryptography (Fernet) | Шифрование медицинских ответов на уровне приложения |
| Инфраструктура | Docker Compose | Запуск одной командой |
| Тесты | pytest, TestClient | 112 тестов, включая все обязательные экстренные сценарии |

## API v1

| Метод | Путь | Назначение |
|---|---|---|
| GET | `/api/v1/health` | Проверка работоспособности |
| POST | `/api/v1/sessions` | Новая сессия: дисклеймер, первый вопрос, `session_token` |
| GET | `/api/v1/sessions/{id}` | Текущее состояние (восстановление после перезагрузки) |
| POST | `/api/v1/sessions/{id}/answers` | Ответ на текущий вопрос |
| POST | `/api/v1/sessions/{id}/back` | Вернуться к предыдущему вопросу |
| DELETE | `/api/v1/sessions/{id}` | Удалить все свои данные |
| POST | `/api/v1/integrations/max/auth` | Вход из MAX: `{token}` из URL → сессия, приветствие |

Все запросы к сессии требуют заголовок `X-Session-Token`.

## Вход из мини-приложения MAX

1. Пользователь открывает бота https://max.ru/id6685107786_bot и нажимает кнопку нашего сервиса.
2. Мини-приложение открывает наш URL с параметром `?token=<JWT>`; JWT живёт 5 минут.
3. Фронтенд сразу забирает `token`, стирает его из адресной строки (`history.replaceState`)
   и отправляет на `POST /api/v1/integrations/max/auth`.
4. Бэкенд один раз вызывает core: `GET {CORE_URL}/api/v3/users/user-for-external-service?token=<JWT>`
   с заголовком `Authorization: Bearer <CORE_SERVICE_TOKEN>`. Сервисный токен есть только на сервере.
5. Из профиля берём минимум: `_id` (хранится только как HMAC), возрастную группу (из даты
   рождения) и пол. Имя показывается в приветствии и не сохраняется. СНИЛС, полис ОМС,
   ФИО и телефон отбрасываются сразу и в БД не попадают.
6. Первый вопрос: «Для кого вы ищете помощь?». «Для себя» — возраст и пол подставляются из
   профиля (в истории помечены «из профиля MAX»). «Для другого человека» — бот спрашивает
   их, потому что профиль описывает владельца аккаунта, а помощь может быть нужна ребёнку.
7. Без `token` (страница открыта не из бота) сервис работает анонимно и подсказывает открыть его из бота.

Ошибки core: 401 — ссылка устарела (просим открыть бота заново), 404 — пользователь не найден,
403/5xx/сеть — 502 «Сервис авторизации временно недоступен», с возможностью продолжить без входа.

## Безопасность и ФЗ-152

- Не собираются ФИО, телефон, адрес, точный возраст (только возрастная группа).
- Из свободного текста автоматически вырезаются телефоны, e-mail и длинные номера документов.
- Ответы и рекомендации хранятся в БД зашифрованными (Fernet: AES-128-CBC + HMAC-SHA256).
- В БД хранится только SHA-256 токена сессии; ID пользователя MAX — только как HMAC.
- Из профиля MAX сохраняются только возрастная группа и пол (зашифрованы); СНИЛС, ОМС, ФИО и телефон отбрасываются.
- Сервисный токен core лежит только в `.env` на сервере.
- Сессии удаляются автоматически через 24 часа; пользователь может удалить данные сам.
- Порт БД не публикуется наружу, backend работает не от root, ответы API не кешируются.
