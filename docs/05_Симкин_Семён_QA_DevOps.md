# Отчёт инженера по тестированию и DevOps

**Участник:** Симкин Семён
**Роль:** QA (pytest, тестовые сценарии) и DevOps (Docker Compose)

## Что сделано

### Автотесты (pytest) — 112 тестов, все проходят

| Файл | Что проверяет | Кол-во |
|---|---|---|
| `tests/test_red_flags.py` | Все 10 экстренных состояний из ТЗ (+ мысли о вреде себе): вариантом ответа, экраном безопасности, комбинацией ответов и свободным текстом; прерывание опроса; маршрут в скорую | 33 |
| `tests/test_triage.py` | Специальность, срочность, место обращения; дети → педиатр; факторы риска; беременность; отсутствие лекарств и дозировок в рекомендациях | 21 |
| `tests/test_dialog.py` | Порядок вопросов, условные вопросы, прогресс, валидация, распознавание текста, очистка ПДн | 26 |
| `tests/test_api.py` | Сквозной сценарий через HTTP, экстренный сценарий и «Назад», 403/404/409/422, удаление данных, шифрование в БД, автоочистка, заголовок no-store | 11 |
| `tests/test_max.py` | Вход из MAX: формат запроса к core (Bearer, URL без двойного слэша), ошибки 401/403/404/500, расчёт возрастной группы, отсутствие СНИЛС/ФИО/телефона в БД, предзаполнение и «Назад», вопрос «Для кого» | 21 |

Ключевые приёмы:
- **Параметризация** (`@pytest.mark.parametrize`): один тест прогоняется на всех экстренных
  состояниях и фразах — легко добавить новый случай.
- **Тесты движка без БД:** медицинская логика проверяется напрямую, быстро и изолированно.
- **API-тесты на SQLite в памяти:** зависимость `get_db` подменяется, каждый тест получает чистую БД.
- **Тест безопасности рекомендаций:** регулярное выражение ищет «мг», «таблетк»,
  «антибиотик», названия препаратов — их быть не должно.

Запуск: `docker compose run --rm tests` или `cd backend && pytest`. Весь набор проходит меньше чем за секунду.

### Docker Compose

| Сервис | Образ | Назначение |
|---|---|---|
| `db` | postgres:16-alpine | БД, том `pgdata`, healthcheck `pg_isready`, порт наружу не открыт |
| `backend` | python:3.12-slim | FastAPI (uvicorn), запускается после готовности БД, healthcheck `/api/v1/health`, не от root |
| `frontend` | node:20 → nginx:1.27-alpine | Многоэтапная сборка: собрали React, отдаём статику nginx; порт 8080 |
| `tests` | образ backend | Профиль `tests`, запускает pytest |

Запуск: `cp .env.example .env && docker compose up --build`, затем http://localhost:8080.
Compose откажется запускаться без ключа шифрования и соли — защита от запуска с пустыми секретами.

## Вопросы комиссии

1. **Как вы проверяете, что бот ловит все экстренные состояния?**
   Параметризованные тесты на каждое из 10 состояний ТЗ: через вариант ответа, через экран
   безопасности и через фразы свободного текста. Проверяется статус `emergency` и то, что
   следующий вопрос не выдаётся.
2. **Какое покрытие тестами?**
   Покрыты все модули предметной логики и все эндпоинты API; 112 тестов. Процент покрытия
   можно посчитать pytest-cov; в приоритете были медицински значимые сценарии.
3. **Почему тесты API на SQLite, а не на PostgreSQL?**
   Скорость и изоляция: каждый тест получает чистую БД в памяти. Модели не используют
   специфичных функций PostgreSQL. Тот же набор можно запустить против PostgreSQL через
   переменную `DATABASE_URL`.
4. **Как проверяется, что бот не назначает лекарства?**
   Тест собирает весь текст рекомендаций по разным сценариям и ищет запрещённые слова
   («мг», «таблетк», «капсул», названия препаратов, «диагноз:»).
5. **Что делает healthcheck и зачем depends_on с условием?**
   Backend стартует только когда PostgreSQL реально принимает подключения, а не просто
   запущен контейнер. Healthcheck backend проверяет и API, и доступ к БД.
6. **Зачем многоэтапная сборка фронтенда?**
   Итоговый образ — только nginx и готовые файлы, без Node.js и исходников: он меньше и безопаснее.
7. **Как храните секреты?**
   В файле `.env`, который не попадает в git (есть `.gitignore`); в репозитории только
   `.env.example`. Без ключей compose не запустится.
8. **Как развернуть на сервере?**
   Скопировать репозиторий, создать `.env` с новыми ключами, `docker compose up -d --build`,
   поставить перед nginx HTTPS (например, Let's Encrypt). Для мини-приложения MAX нужен HTTPS. В `.env` задаётся `CORE_SERVICE_TOKEN`.
9. **Как тестировали интерфейс?**
   Вручную по сценариям из отчёта менеджера (самопомощь, экстренный текст, ребёнок с
   температурой, травма, «Назад»). Автотесты интерфейса — следующий шаг (Playwright).
10. **Что будет, если упадёт база?**
    Healthcheck пометит backend нездоровым, Docker перезапустит контейнеры
    (`restart: unless-stopped`), данные сохранятся в томе `pgdata`.
