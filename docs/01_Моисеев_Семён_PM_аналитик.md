## 2. Задача и как мы её поняли

По ТЗ нужен чат-бот в мессенджере Макс, который:
1. собирает жалобы (категории + свободный текст + локализация);
2. собирает анамнез (хронические болезни, лекарства, аллергии, операции, наследственность,
   беременность, вредные привычки);
3. непрерывно ищет экстренные признаки и при их обнаружении сразу прерывает опрос;
4. выдаёт карточку: специалист, срочность, место обращения, обоснование;
5. показывает дисклеймеры в начале и в конце, не ставит диагноз и не назначает лекарства;
6. защищает персональные данные (ФЗ-152).

Организаторы выдали бота с мини-приложением и API core. Мини-приложение открывает наш
веб-сервис и передаёт в адресе 5-минутный токен пользователя; наш бэкенд обменивает его
в core на профиль. Мы берём из профиля только возраст и пол — остальное (СНИЛС, ОМС, ФИО,
телефон) не сохраняем.

Дополнительные задания (LLM, голос, история, тип оплаты) сознательно не делали: фокус на
надёжности основной функции и безопасности маршрутизации, за которые даётся больше баллов.

## 4. Предметная модель (аналитика)

### 4.1. Сценарий диалога

1. Дисклеймер, кнопка «Начать». При входе из MAX — приветствие по имени и вопрос
   «Для кого вы ищете помощь?» (для себя — возраст и пол из профиля).
2. Жалоба: категория или свободный текст.
3. Уточнение (локализация), зависит от категории.
4. Экран безопасности: «Есть ли сейчас что-то из списка?» — 8 экстренных признаков + «Ничего».
5. Возрастная группа (точный возраст не нужен), пол.
6. Длительность, выраженность.
7. Анамнез: хронические заболевания, лекарства, аллергии, операции, наследственность,
   беременность (по условию), вредные привычки (необязательно).
8. Карточка рекомендации и финальный дисклеймер.

Жалоба и экран безопасности стоят первыми намеренно: экстренное состояние выявляется на
1–3-м вопросе, а не после 14-го.

### 4.2. Экстренные признаки (red flags)

Каждый признак ловится тремя способами: вариант ответа, комбинация ответов, свободный текст.

| Код | Состояние из ТЗ | Как выявляется |
|---|---|---|
| CHEST_PAIN | Боль в груди | Боль → «Грудная клетка»; экран безопасности; текст «давит в груди» |
| DYSPNEA_REST | Одышка в покое | Дыхание → «Нехватка воздуха в покое»; экран; текст «задыхаюсь» |
| LOSS_OF_CONSCIOUSNESS | Потеря сознания | Неврология → «Обморок»; экран; текст «потерял сознание» |
| SEIZURES | Судороги | Неврология → «Судороги»; экран; текст |
| BLEEDING | Кровотечение | ЖКТ → «Кровь в рвоте или стуле»; экран; текст |
| STROKE | Признаки инсульта (FAST) | Неврология → «Слабость половины тела…»; экран; текст «перекосило лицо» |
| ANAPHYLAXIS | Анафилаксия | Кожа → «Внезапный отёк лица»; экран; текст «отёк горла» |
| ACUTE_ABDOMEN | Острая боль в животе | Экран; боль в животе + выраженность «сильно/невыносимо»; текст |
| CHILD_HIGH_FEVER | Температура > 39,5 у ребёнка | Температура «выше 39,5» + возраст до 18 лет; число в тексте > 39,5 |
| HEAD_TRAUMA_LOC | Травма головы с потерей сознания | Травма → «Голова, была потеря сознания»; текст |
| SUICIDAL | (дополнительно) | Настроение → «Мысли о причинении вреда себе»; текст |

Принцип **over-triage**: при сомнении бот выбирает более срочный вариант. Отрицания в тексте
(«нет боли в груди») не разбираются: лучше лишний раз показать экстренную карточку, чем
пропустить инфаркт. Ошибочный ответ можно отменить кнопкой «Я ошибся в ответе — вернуться».

### 4.3. Правила маршрутизации

1. **Экстренно** → скорая 103/112, если найден любой экстренный признак.
2. **Срочно (24 ч)**, если есть хотя бы одно: сильная или невыносимая выраженность;
   температура > 39,5 у взрослого; > 38,5 дольше 3 дней; любая температура у ребёнка до года;
   высокая температура при диабете, онкологии или болезнях сердца; любая травма; внезапная
   потеря зрения или травма глаза; ожог; одышка при нагрузке; беременность + боль, ЖКТ или
   температура; возраст 65+ с температурой или проблемами дыхания.
   Место: травмы, ожоги и глаза — приёмный покой или травмпункт, остальное — поликлиника в день обращения.
3. **Самопомощь** → аптека (альтернатива — телемедицина), только если одновременно: лёгкий
   симптом из «безопасного» списка (насморк, кашель, изжога, температура до 38,5 и т. п.),
   выраженность «слабо», длительность до 3 дней, нет факторов риска (младенец, 65+,
   беременность или лактация, хронические болезни).
4. **Планово** → поликлиника (для части жалоб альтернатива — телемедицина) во всех остальных случаях.

Специальность: по категории и уточнению (голова → невролог, зубы → стоматолог, порез →
хирург и т. д.); если пациенту меньше 18 и нужен терапевт — педиатр.

Карточка содержит обоснование (почему так решили) и практические советы: что сообщить врачу
(хронические заболевания, лекарственная аллергия, беременность), что взять с собой.

## 5. Архитектура и стек (обоснование выбора)

- **Python + FastAPI + Pydantic** — быстрая разработка, строгая валидация входных данных,
  автоматическая документация API (Swagger).
- **PostgreSQL + SQLAlchemy 2.0** — надёжная промышленная СУБД; ORM позволяет гонять тесты
  на SQLite без отдельного сервера.
- **React + Vite** — лёгкое одностраничное приложение (≈50 КБ), быстро открывается в WebView
  мессенджера.
- **Docker Compose** — весь проект (БД, API, интерфейс) поднимается одной командой.
- Медицинская логика — **отдельный слой на чистом Python** (`domain/`), не зависит от БД и
  веба. Её можно перенести в любой канал (мини-приложение, текстовый бот) и полностью покрыть тестами.

## 6. Безопасность и ФЗ-152

- **Минимизация:** не спрашиваем ФИО, телефон, адрес, полис, точный возраст, названия лекарств.
- **Очистка текста:** телефоны, e-mail и номера документов вырезаются из свободного текста до сохранения.
- **Шифрование:** ответы и обоснование хранятся в БД в зашифрованном виде (Fernet).
- **Псевдонимизация:** ID пользователя MAX хранится только как HMAC; из профиля core берутся только возраст и пол.
- **Доступ:** у каждой сессии свой секретный токен, в БД — только его хеш.
- **Срок хранения:** 24 часа, затем автоматическое удаление; пользователь может удалить данные сам.
- **Инфраструктура:** БД не видна снаружи, API не кешируется, сервис работает не от root.

## 7. Качество

112 автотестов pytest, все проходят: все 10 обязательных экстренных состояний (вариантом
ответа и свободным текстом), маршрутизация, валидация, кнопка «Назад», шифрование в БД,
проверка доступа, удаление и автоочистка данных, отсутствие лекарств в рекомендациях, вход из MAX
(формат запроса к core, обработка ошибок, отсутствие СНИЛС/ФИО/телефона в БД).

## 8. Ограничения MVP и развитие

- Разбор текста по ключевым словам не понимает сложные формулировки и отрицания →
  следующий шаг: LLM или NLP-модель (доп. задание).
- Правила маршрутизации составлены по общим клиническим принципам и требуют проверки
  практикующим врачом перед реальным запуском.
- Вход из MAX реализован по API организаторов; сквозная проверка с живым core — на
  развёрнутом сервере с публичным HTTPS-адресом.
- Развитие: история обращений, учёт типа оплаты (ОМС/ДМС), голосовой ввод, запись к врачу.

## 10. Демонстрационные сценарии

1. **Самопомощь:** Дыхание → Насморк → Ничего → 18–49 → Мужской → 1–3 дня → Слабо → Нет по анамнезу.
   Итог: ЛОР, самопомощь, аптека (или телемедицина).
2. **Экстренный текст:** ввести «давит в груди с утра» → сразу красная карточка «Вызовите скорую 103 или 112».
3. **Ребёнок с температурой:** Температура → Выше 39,5 → Ничего → 1–13 лет → экстренная карточка.
4. **Травма:** Травма → Рука или нога → … → Срочно, травматолог, травмпункт.
5. **Кнопка «Назад»:** в экстренном сценарии нажать «Я ошибся в ответе — вернуться».

## 11. Вопросы комиссии к менеджеру и аналитику

1. **Почему решения принимают правила, а не ИИ?**
   В медицине важны предсказуемость и объяснимость. Каждое решение правил можно объяснить
   и проверить тестом; нейросеть может ошибиться непредсказуемо. ИИ — следующий шаг, и даже
   тогда экстренные признаки должны проверяться правилами.
2. **Откуда медицинские правила? Кто их проверял?**
   Минимальный список экстренных признаков взят из ТЗ, остальное — общепринятые принципы
   сортировки пациентов (срочность по выраженности, длительности, группам риска). Для
   реального запуска правила должен утвердить практикующий врач; база знаний для этого
   вынесена в отдельный файл и имеет версию.
3. **Что будет, если бот пропустит экстренное состояние?**
   Мы снижаем этот риск тремя линиями: экран безопасности для всех, экстренные варианты в
   уточнениях и проверка свободного текста. Бот выбирает более срочный вариант при сомнении,
   а финальный дисклеймер напоминает вызвать скорую при ухудшении.
4. **Как бот понимает, сколько вопросов осталось?**
   Он считает только применимые вопросы. Если пациент мужчина, вопрос о беременности
   исключается, и общее число уменьшается.
5. **Почему возраст группами, а не точной датой?**
   Минимизация персональных данных: для маршрутизации важна группа (младенец, ребёнок,
   взрослый, пожилой), а не дата рождения.
6. **Чем вы отличаетесь от аналогов?**
   Экстренный признак выявляется на первых вопросах и тремя независимыми способами.
   Обоснование показано пользователю прозрачно. Минимум данных и их шифрование, работа
   в мессенджере MAX без установки приложения, вход по профилю без лишних данных.
7. **Почему не сделали дополнительные задания?**
   Сознательный выбор: за надёжность основной функции и безопасность маршрутизации даётся
   больше баллов. Архитектура позволяет добавить LLM и историю обращений без переделки.
8. **Как распределялась работа в команде?**
   Роли закреплены по зонам (см. таблицу в разделе 1), каждый отвечает за свой слой. Я
   формировал требования и медицинскую логику, вёл план и связь с менторами.
9. **Как работает вход из MAX и что вы делаете с профилем?**
   Токен из адреса живёт 5 минут; бэкенд один раз меняет его в core на профиль. Из профиля
   берём только возраст и пол, причём только если пациент — сам владелец аккаунта (поэтому
   первый вопрос «Для кого помощь?»). СНИЛС, ОМС, ФИО и телефон не сохраняем.
10. **Может ли бот навредить советом?**
    Бот не называет лекарства и дозировки (это проверяет тест), не ставит диагноз, при любом
    сомнении повышает срочность и всегда напоминает про скорую.
