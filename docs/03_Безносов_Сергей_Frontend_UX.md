# Отчёт frontend-разработчика и UX-дизайнера

**Участник:** Безносов Сергей
**Роль:** frontend-разработчик, UX (React-интерфейс, вход из мини-приложения MAX)

## Что сделано

Интерфейс на **React 18 + Vite**, в продакшене раздаётся через **nginx**. Размер сборки
около 50 КБ (gzip), поэтому приложение быстро открывается в WebView мессенджера.

| Файл | Назначение |
|---|---|
| `src/App.jsx` | Состояние приложения, вызовы API, восстановление сессии после перезагрузки |
| `src/components.jsx` | Экраны: стартовый, история диалога, вопрос, экстренная карточка, итоговая карточка |
| `src/api.js` | Клиент API, токен в заголовке (не в адресной строке) |
| `src/maxBridge.js` | Забирает `token` из URL мини-приложения и стирает его из адресной строки |
| `src/styles.css` | Строгий корпоративный стиль, адаптация под телефон |
| `nginx.conf` | Раздача статики, проксирование `/api`, заголовки безопасности |

### Экраны и UX-решения

- **Стартовый экран:** что делает сервис, сколько времени займёт, какие данные не нужны,
  дисклеймер «не ставит диагноз», кнопка «Начать».
- **Диалог в виде чата:** вопросы бота слева, ответы пользователя справа. Видна вся история,
  поэтому понятно, что уже сказано.
- **Прогресс:** «Вопрос N из M» и полоса в шапке (требование ТЗ).
- **Ответы кнопками:** один выбор — нажал и перешёл дальше; несколько — чекбоксы и «Далее».
  Вариант «Нет» автоматически снимает остальные отметки.
- **Свободный текст:** поле для описания своими словами на шаге жалобы и на экране безопасности.
- **«Назад»** на каждом шаге, «Пропустить» для необязательного вопроса.
- **Экстренная карточка:** красная рамка, крупно «Вызовите скорую помощь: 103 или 112»,
  пояснение, кнопки «Позвонить 103» и «Позвонить 112», кнопка «Я ошибся в ответе — вернуться».
- **Итоговая карточка:** цветной статус срочности, специалист, место, альтернатива,
  блок «Почему такая рекомендация», «Что сделать», финальный дисклеймер.
- **«Удалить мои ответы»:** удаляет данные с сервера.

Стиль строгий: тёмно-синяя палитра, без смайликов, стикеров и картинок. Цвет несёт смысл:
красный — экстренно, янтарный — срочно, синий — планово, зелёный — самопомощь. Тон текстов
дружелюбный, без медицинских терминов («Насколько сильно это вас беспокоит?»).

### Вход из MAX

При загрузке страницы `maxBridge.takeLaunchToken()` читает `token` из адреса,
удаляет его через `history.replaceState` и отдаёт на бэкенд (`POST /integrations/max/auth`).
Токен живёт 5 минут, поэтому обмен идёт сразу, ещё до нажатия «Начать». На стартовом экране —
приветствие по имени. Если ссылка устарела или core недоступен, показываем понятное сообщение
и кнопку «Продолжить без входа». Без `token` — подсказка открыть сервис из бота.

мессенджере, поэтому интерфейс привычен. Почти все ответы — кнопки, а свободный ввод есть

## Вопросы комиссии

1. **Почему React и Vite?**
   React — самый распространённый инструмент для интерфейсов, удобная компонентная модель.
   Vite быстро собирает проект; итоговый размер около 50 КБ, что важно для мини-приложения.
2. **Как пользователь понимает, сколько осталось?**
   В шапке «Вопрос N из M» и полоса прогресса. Число M пересчитывается: если вопрос не нужен
   (например, о беременности для мужчины), он не считается.
3. **Что если пользователь случайно закроет страницу?**
   Идентификатор и токен сессии лежат в sessionStorage вкладки; при повторном открытии
   состояние загружается с сервера и диалог продолжается с того же места.
4. **Почему токен не передаётся в URL?**
   Адреса попадают в журналы серверов и историю браузера. Токен идёт в заголовке `X-Session-Token`.
5. **Как сделан экстренный экран?**
   Когда сервер возвращает статус `emergency`, вместо вопроса показывается красная карточка
   с крупным призывом, пояснением и кнопками звонка (`tel:`). Опрос не продолжается.
6. **Как обеспечена доступность?**
   Крупные кнопки, контрастные цвета, `role="alert"` у экстренной карточки и ошибок,
   подписи для прогресса, работа с клавиатуры (обычные кнопки и чекбоксы).
7. **Как сделана адаптация под мобильные?**
   Вёрстка mobile-first, максимальная ширина 600 px; на узких экранах карточка результата
   перестраивается в одну колонку.
8. **Как интерфейс работает внутри MAX?**
   Мини-приложение открывает наш адрес во фрейме с `?token=`. Мы забираем токен, стираем его
   из адреса и меняем на сессию через свой бэкенд. В core браузер не ходит.
9. **Почему нет иконок и смайликов?**
   Медицинский сервис должен выглядеть строго и вызывать доверие. Смысл передаётся текстом и
   цветом статуса.
10. **Как защищён фронтенд?**
    nginx отдаёт заголовки Content-Security-Policy, nosniff и no-referrer. React экранирует
    вывод, поэтому текст пользователя не может внедрить скрипт.
